# Day 3 — Test-Data Manager Reflection

During this exercise, I used a set (`seen_ids`) to track test case IDs and remove duplicates while keeping the first occurrence of each test case. I used a dictionary (`lookup`) to store test cases by their IDs so I could retrieve specific records quickly. Using a list for lookups would require looping through the records each time, making the process less efficient as the number of test cases increases. Working on a feature branch allowed me to develop and test my code without affecting the `main` branch until everything was ready to merge. One issue I encountered was accidentally renaming my feature branch to `main` instead of renaming `master`, which I fixed using the correct Git branch renaming commands. By the end, I successfully merged my feature branch into `main` and passed all five self-checks.
